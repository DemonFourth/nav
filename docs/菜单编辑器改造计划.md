> 目标：将现有菜单编辑器改造为预览文件 `preview-menu-editor.html` 的完整功能和 UI

## 一、架构关系

```
useBookmarks.js (共享底层 API，模块级单例)
├── categories ref ← 两边共享
├── bookmarks ref  ← 两边共享
├── addCategory()     POST /api/categories
├── updateCategory()  PUT  /api/categories/:id
├── deleteCategory()  DELETE /api/categories/:id
├── deleteBookmark()  DELETE /api/bookmarks/:id
└── reorderItems()    POST /api/reorder

┌─────────────────────────────┬──────────────────────────────────────┐
│ 默认模式                     │ Nav 模式（本次改造）                  │
│                             │                                      │
│ App.vue                     │ NavSettingsModal.vue                 │
│   └→ 直接用 useBookmarks    │   ├── 菜单 tab → useCategoryEditor   │
│ CategoryDialog.vue          │   │     └→ 包装 useBookmarks + pending│
│   └→ 直接用 useBookmarks    │   └── 书签 tab (新增)                │
│                             │                                      │
│ 即时 API 调用                │   分类：本地优先 + pending 批量保存   │
│                             │   书签：即时 API 调用                 │
└─────────────────────────────┴──────────────────────────────────────┘
```

**重要**：`useCategoryEditor.js` 仅在 `NavSettingsModal.vue` 中使用，改造**不影响默认模式**。

### 3.2 新增工具函数

| 函数 | 说明 | 返回值 |
|------|------|--------|
| `findItem(id)` | 在分类树中查找分类对象 | `Category \| null` |
| `findParentOf(id)` | 查找分类的父节点 | `Category \| null` |
| `getPath(id)` | 获取分类完整路径（如 "技术文档 > Vue.js"） | `string` |
| `getSiblings(id)` | 获取某分类的兄弟节点数组 | `Category[]` |
| `removeItemById(id)` | 从树中移除分类并返回该对象 | `Category \| null` |
| `isDescendant(parentId, childId)` | 检查是否是后代分类 | `boolean` |
| `getItemName(id)` | 获取分类名称 | `string` |

### 3.3 修改现有函数

| 函数 | 当前行为 | 改造后行为 |
|------|----------|------------|
| `selectCategory(category)` | 设置表单值 | **增加**：捕获初始快照 + 设置 `formOriginal` |
| `onMoveUp(id)` | 修改 editForm.position | **改为**：本地移动兄弟节点 + `pendingChanges.push({ type: 'reorder' })` + toast |
| `onMoveDown(id)` | 修改 editForm.position | **改为**：本地移动兄弟节点 + `pendingChanges.push({ type: 'reorder' })` + toast |
| `moveChildItem(...)` | 本地移动（无 pending） | **增加**：记录 pending 变更 + toast |
| `onDrop(event, category)` | 仅重置拖拽状态（stubbed） | **完善**：真正执行节点移动（before/after/child 三种模式）+ 记录 pending + toast |
| `applyChanges()` | 调用 API 更新 | **改为**：仅本地更新 name/parent_id + 记录 rename/move 变更 + 更新 `formOriginal`，**不调用 API** |
| `createCategory(...)` | 调用 API 创建 | **改为**：仅本地添加 + 记录 create 变更 + toast |
| `removeCategory(id)` | 调用 API 删除 | **改为**：仅本地移除 + 记录 delete 变更 + toast |

### 3.4 新增函数

| 函数 | 说明 |
|------|------|
| `captureInitialSnapshot()` | 深拷贝当前 categories 作为初始快照 |
| `recordChange(change)` | 向 pendingChanges 添加变更记录 |
| `moveRootItem(id, direction)` | 移动根分类位置 + 记录 pending |
| `resetForm()` | 恢复表单为 `formOriginal` 的值 |
| `applyFormChanges()` | 本地更新 name/parent + 记录变更 + 更新 `formOriginal` |
| `confirmAddCategory(name, parentId)` | 本地创建分类 + 记录 create 变更 |
| `confirmDelete(id)` | 本地删除分类 + 记录 delete 变更 |
| `confirmSave()` | 调用 `reorderItems` 批量保存，失败回滚 |
| `discardAll()` | 二次确认后恢复初始快照 + 清空 pending |
| `getChangeDescription(change)` | 返回变更的可读描述文本 |
| `getChangeTypeLabel(type)` | 返回变更类型的中文标签 |
| `getPendingChangeCount()` | 返回 `pendingChanges.length` |
| `hasPendingChanges()` | 返回 `pendingChanges.length > 0` |

### 3.5 `confirmSave` 详细逻辑

```
1. 保存当前状态用于回滚：rollbackSnapshot = deepClone(categories.value)
2. 构建 reorder payload：展平分类树为 { id, position, parent_id } 列表
3. 调用 reorderItems('categories', items)
4. 成功 → 清空 pendingChanges、更新 initialDataSnapshot、toastSuccess('保存成功')
5. 失败 → categories.value = rollbackSnapshot、toastError('保存失败，已回滚')
```

### 3.6 `discardAll` 详细逻辑

```
1. 弹出二次确认："确定要放弃全部更改吗？此操作不可恢复。"
2. 用户确认 → categories.value = deepClone(initialDataSnapshot.value)
3. pendingChanges.value = []
4. selectedCategoryId.value = null
5. toastWarning('已放弃全部更改')
```

#### 书签删除逻辑

```javascript
async function deleteBookmarkItem(bookmark) {
  if (!confirm(`确定要删除书签 "${bookmark.name}" 吗？`)) return
  const result = await deleteBookmark(bookmark.id)
  if (result.success) {
    toastSuccess('已删除书签')
  } else {
    toastError(result.error || '删除失败')
  }
}

async function batchDeleteBookmarks() {
  const ids = Array.from(selectedBookmarks.value)
  if (ids.length === 0) return
  if (!confirm(`确定要删除 ${ids.length} 个书签吗？`)) return
  const result = await batchOperation('delete', ids)
  if (result.success) {
    toastSuccess(`已删除 ${ids.length} 个书签`)
    selectedBookmarks.value.clear()
  } else {
    toastError('批量删除失败')
  }
}
```

## 七、风险点与注意事项

### 7.1 拖拽功能

- 拖拽是本次改造的**核心难点**，需要正确处理：
  - 同父节点内移动时的索引偏移（向下移动需 -1）
  - 跨父节点移动时的目标索引计算
  - 成为子分类时自动展开目标父节点
  - 防止循环引用（不能将分类拖入自己的后代）

### 7.2 共享 categories ref

- Nav 模式的 pending 操作会**立即反映**到默认模式的 UI 上（因为共享 `categories.value`）
- "放弃"操作会回滚 `categories.value`，默认模式的 UI 也会跟着回滚
- 这是预期行为，但需注意用户可能产生的困惑

### 7.3 reorderItems API

- 需要确认后端 `POST /api/reorder` 接口是否支持同时更新 `position` 和 `parent_id`
- 如果后端只支持 position 排序，则 parent_id 变更需要单独调用 `PUT /api/categories/:id`

### 7.4 书签 tab 性能

- 如果书签数量超过 500，需要考虑分页或虚拟滚动
- 初期可全部加载，后续根据实际数据量优化

### 7.5 CSS 变量

- 使用现有 CSS 变量（`--accent`、`--card-border`、`--card-bg` 等）保持风格一致
- 避免硬编码颜色值
